# Проверка производительности

Критерии релиза из ТЗ:

- 500 событий принимаются и доставляются не более чем за 60 секунд на трёх worker-репликах;
- каждый ответ ingest имеет статус `202`, не является дублем и создаёт хотя бы одно сообщение;
- p95 времени ответа ingest не превышает 50 мс;
- `hookline_messages_pending` и `hookline_messages_in_flight` возвращаются к нулю.

Полная автоматическая проверка сама создаёт приложение, быстрый sink endpoint и
подписку, запускает нагрузку и проверяет очередь:

```bash
cp .env.example .env
make release-verify
```

Чтобы проверить только нагрузку на уже запущенном стенде, сначала создайте
приложение и минимум один активный endpoint с подходящей подпиской. Endpoint
должен выдерживать требуемую скорость доставки.

```bash
APP_ID=<uuid> \
COUNT=500 \
PARALLEL=25 \
P95_MAX_MS=50 \
DRAIN_TIMEOUT_SECONDS=60 \
./scripts/load.sh
```

Успешный запуск заканчивается строкой `PASS` с количеством принятых событий,
созданных сообщений, p95, состоянием очереди и полным временем прогона. Любое
нарушение критерия завершает скрипт ненулевым кодом.

Результат зависит от CPU, диска и Docker. Перед тегом `v1.0.0` сохраните строку
`PASS`, дату, commit SHA и характеристики целевого окружения в release notes.
